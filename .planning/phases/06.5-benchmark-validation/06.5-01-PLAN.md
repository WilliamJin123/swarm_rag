    swarm_rag_module/swarm_rag/benchmark/performance_benchmark.py

  <action>
Fix the StarkVectorStore constructor call in `_run_evolution()` method.

**Bug 1: Device mismatch (CRITICAL)**
The current code on line 529:
```python
vector_store = StarkVectorStore(doc_embs, device=resolved_device)
```
Should be:
```python
vector_store = StarkVectorStore(doc_embs, doc_ids, device=resolved_device)
```

The `StarkVectorStore.__init__` signature is `(embeddings: torch.Tensor, ids: torch.Tensor, device=...)`. Missing `doc_ids` causes the `device` kwarg to be misinterpreted, leading to CPU tensors when GPU expected.

**Bug 2: Memory growth investigation**
Add explicit memory cleanup after data loading but before evolution starts:
```python
# After loading all data and before creating retriever
import gc
gc.collect()
if self._has_cuda:
    torch.cuda.empty_cache()
```

Also add a memory snapshot log right before evolution starts to verify starting memory is reasonable:
```python
if self._has_cuda:
    allocated_mb = torch.cuda.memory_allocated() / (1024 * 1024)
    total_mb = torch.cuda.get_device_properties(0).total_memory / (1024 * 1024)
    logger.info(f"Memory before evolution: {allocated_mb:.0f}MB / {total_mb:.0f}MB ({allocated_mb/total_mb:.1%})")
```

**Verification checklist:**
- StarkVectorStore receives both `doc_embs` AND `doc_ids`
- StarkPreComputedEmbeddingHandler receives both `query_embs` AND `query_ids` (already correct)
- Memory cleanup happens before evolution loop starts
- Starting memory logged for debugging
