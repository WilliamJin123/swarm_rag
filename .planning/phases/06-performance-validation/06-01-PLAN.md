1. Create `__init__.py` exporting `PerformanceBenchmark`, `BenchmarkResult`, `BenchmarkConfig`

2. Create `performance_benchmark.py` with:

**BenchmarkConfig dataclass:**
- `population_size: int = 75`
- `target_generations: int = 500`
- `time_limit_hours: float = 3.0`
- `memory_limit_gb: float = 4.0`

**BenchmarkResult dataclass:**
- All fields from JSON schema in RESEARCH.md (timestamp, pass, config, results, system_info, pass_criteria)
- `to_dict()` method for JSON serialization
- `to_console_summary()` method matching console format in RESEARCH.md

**PerformanceBenchmark class:**
- `__init__(config: BenchmarkConfig)` - stores config, initializes timing arrays
- `_collect_system_info() -> dict` - collects Python, PyTorch, CUDA, GPU info (use pattern from RESEARCH.md)
- `_extrapolate_time(actual_gens, actual_time_sec, target_gens=500) -> Tuple[float, bool]` - linear extrapolation for early convergence
- `run() -> BenchmarkResult` - main benchmark method:
  1. Load STARK Prime data (full dataset for realistic performance)
  2. Configure EvolutionEngine with population=75, generations=500, convergence enabled
  3. Record start time with `torch.cuda.synchronize()` before timing (per RESEARCH.md pitfall)
  4. Run evolution via engine
  5. Collect per-generation timing from `GenerationProfiler`
  6. Collect peak memory from `MemoryLogger`
  7. Collect cache stats from `FitnessCache.total_stats` and `EmbeddingCacheProvider.get().stats`
  8. If converged early, extrapolate time to 500 gens
  9. Determine pass/fail based on projected time < 3h AND peak memory < 4GB
  10. Return `BenchmarkResult`

**Important implementation details:**
- Use `torch.cuda.synchronize()` before all timing measurements (avoid async timing pitfall)
- Use `torch.cuda.memory_allocated()` not `memory_reserved()` (per decision [01-01])
- Track `torch.cuda.max_memory_allocated()` for peak, reset with `reset_peak_memory_stats()` at start
- Handle CPU-only case (no CUDA available) - skip GPU-specific metrics
- Extract termination_reason from orchestrator's `_termination_reason` attribute

Create `run_benchmark.py` as CLI entry point:

1. Add argparse with optional overrides:
   - `--population` (default 75)
   - `--generations` (default 500)
   - `--time-limit` (default 3.0 hours)
   - `--memory-limit` (default 4.0 GB)
   - `--output` (default `.planning/phases/06-performance-validation/benchmark-results.json`)

2. Main logic:
   ```python
   if __name__ == "__main__":
       args = parse_args()
       config = BenchmarkConfig(
           population_size=args.population,
           target_generations=args.generations,
           time_limit_hours=args.time_limit,
           memory_limit_gb=args.memory_limit,
       )
       benchmark = PerformanceBenchmark(config)
       result = benchmark.run()

       # Print console summary
       print(result.to_console_summary())

       # Write JSON report
       output_path = Path(args.output)
       output_path.parent.mkdir(parents=True, exist_ok=True)
       with open(output_path, 'w') as f:
           json.dump(result.to_dict(), f, indent=2)

       # Exit with appropriate code
       sys.exit(0 if result.overall_pass else 1)
   ```

3. Run the benchmark:
   ```bash
   cd swarm_rag_module
   python -m swarm_rag.benchmark.run_benchmark --output ../.planning/phases/06-performance-validation/benchmark-results.json
   ```

**Expected output:**
- Console summary printed to stdout
- JSON report written to `.planning/phases/06-performance-validation/benchmark-results.json`
- Exit code 0 if pass, 1 if fail

**Note:** This may take significant time (potentially hours if running to 500 gens or until convergence). The benchmark is designed to allow convergence early-stop with extrapolation.
